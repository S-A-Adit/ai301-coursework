# Rubric: is this reproduction package ready to post?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| environment-recorded | The repro report's environment line (eval: the bundle's repro report; live: the draft repro comment), read against the issue's stated target version and its repo's bug-report template. | Pass if the report states the value for each field the template asks about (version, OS, and any other environment specific that bears on this issue) — either by pasting a command's raw output or by stating the equivalent value directly (e.g. "conda 26.7.0, Python 3.12.7, macOS 15.5, libmamba solver" satisfies a template field asking for `conda info`'s contents). Pasting raw command output is not required on its own. If the tested version or environment differs from what the issue names, pass only if the report says so explicitly (e.g. "issue filed against 0.63.1, tested on 0.64.1"). Fail only if a value for a field that bears on this issue is missing outright, or a version/environment difference from the issue is left unstated. | required |
| steps-rerunnable | The repro report's steps/commands section. | Pass if the steps give, in order from a stated starting state, either the literal commands/input run or a description precise enough that a stranger could reconstruct the exact input from it (naming exactly which fields/values are present, not just "a config file" or "test data") — including the specific step that triggers the behavior the issue describes. Fail if a step is vague prose that does not pin down the input ("set up the project"), if a needed input or config is referenced without either its content or a fully specific description of it, or if the triggering step is skipped, generalized, or altered from what the issue describes. | required |
| behavior-matches-issue | The repro report's shown output or artifact, read against the issue's described trigger and failure mode (not the issue's title or general topic). | Pass if the artifact demonstrates the same trigger and the same failure mode the issue describes — not a different error, a different exit behavior, or a graceful failure standing in for a crash or silent no-op — OR the report states outright that it could not reproduce the behavior and names what about its own environment or steps differs from a setup that plausibly would trigger it. Fail if the artifact shows an adjacent symptom or a different mechanism, or if an unstated deviation (changed input syntax, an older version, an altered command) produced the shown result instead of the one the issue reports. | required |
| honest-conclusion | The report's stated conclusion (the "expected/actual" or summary lines), compared against the artifacts shown earlier in the same report. | Pass if every claim in the conclusion ("confirmed", "reproducible", "root cause is X", "happens every time") is directly backed by an artifact shown in the report. Fail if the conclusion asserts more than its own shown evidence supports — a diagnosis with no run behind it, a certainty claim with no corresponding transcript, or a claimed frequency/scope no artifact establishes. | required |
| claim-comment-intent | The candidate claim comment's text. | Pass if the comment names the specific issue or behavior being taken on (something a generic template could not have produced for this issue) and states a concrete next step in the claimant's own words. Fail if the comment is interchangeable "assign me" / "+1" boilerplate that cites nothing specific to this issue, or promises a guaranteed outcome or timeline it has no basis for. | required |
| ai-disclosure | The repo's contribution/AI-use policy (eval: the repo-facts block; live: the repo's CONTRIBUTING doc or README per `references/evidence-guide.md`), compared against the claim and repro comments together. | Pass if the repo's stated policy does not require AI-use disclosure, or if it does and at least one of the comments discloses it. Fail only if the policy explicitly requires disclosure and no comment discloses it. | required |

## Verdict rule

Accept if and only if every required check passes. There are no preferred checks in this rubric; every proof family named in SKILL.md (environment, steps, behavior shown, honesty, comms/disclosure) gates the verdict directly, because each one names a distinct way a package has actually gotten rejected.

A required check graded `unclear` counts as a failure: proof that cannot be verified is proof that is not ready to post.

In live mode, claim-only drafts are graded only on `claim-comment-intent` and, if the repo's policy already appears in `scope.md`'s house rules, `ai-disclosure`; the other checks read the repro report and are not yet applicable, per SKILL.md's claim-only rule.
